# 附魔台 RNG 助手（Minecraft Java）

反推 Minecraft Java 版附魔台背后那串随机数。手机上打开就能用：记下附魔台三档显示的数字，算出你存档当前的附魔种子（XpSeed），从而知道**点哪一档会出什么**，或者**还要再附魔几次才能刷到想要的**。

- 纯前端单文件，不联网、不要权限、不上传任何数据
- 手机 App（Android，约 105 KB）和网页版共用同一套界面与算法
- 支持 1.21.4 – 26.3（含长矛 / 突刺）

## 它是怎么算的

附魔台三档结果不是当场随机的，而是由玩家存了一个 32 位整数 `XpSeed` 决定：

```
每次打开附魔台：rand.setSeed(XpSeed)
每档各取 2 个随机数：
  i = nextInt(8) + 1 + floor(书架数 / 2) + nextInt(书架数 + 1)
  第 1 档 = max(i / 3, 1)
  第 2 档 = i * 2 / 3 + 1
  第 3 档 = max(i, 书架数 * 2)
```

具体出哪些附魔，是再用 `XpSeed + 档位` 重新播种后独立生成的：先按物品的附魔能力算出等级代价，再在「这件物品能出、且等级区间命中」的附魔里按权重抽，然后反复 `nextInt(50) <= 等级` 判断要不要再加一条（每加一条等级减半）。

所以只要知道三档数字（再加上书架数），就能把 32 位种子暴力出来 —— 本工具用 WebAssembly 扫完 2^32 个种子，手机上多线程大约 4 秒。

换种子也很简单：附魔一次，玩家随机数往前走一格，`XpSeed` 换成下一个 `nextInt()`。

## 怎么用

1. **准备**：15 个书架、能附魔的物品、≥30 级经验、一把精准采集（不带耐久）的斧子
2. **记录**：把书架摆好，逐档记下附魔台显示的数字；记完一组就挖掉/堵住一个书架再记下一组
3. **破解**：一般 6 组数字就能唯一确定种子（平均一组 4–5 位信息，32 位理论上要 7 组，但实际 6 组常常只剩 1 个候选，不够会提示再加一组）
4. **看结果**：这一档会出什么、对比建议组合、差哪几级
5. 想要的东西刷不出来就走**刷种**分支：算还需要附魔几次、每次该投几件物品

## 构建

网页版（根目录的 `index.html` 就是它）：

```bash
./build.sh          # 需要 python3、clang（wasm32 目标）
```

Android APK：

```bash
cd apk-src
# 需要 aapt2 / javac / d8 / zipalign / apksigner
./build_apk.sh <versionCode> <versionName>
```

## 目录

```
index.html     单文件网页版（向导式，推荐）
full.html      标签版（预测 / 破解 / 刷种 / 附魔表 / 说明 / 教程）
tutorial.html  图文教程
src/           源码：wiz/ 向导版界面，build/ 引擎与标签版，wasm/ 扫描内核
data/          从 Minecraft 26.3 数据包提取的附魔与物品定义
apk-src/       Android 外壳（WebView + 原生剪贴板、返回键桥）
tests/         jsdom 自动化测试
```

## 数据来源

- 附魔与物品定义：`misode/mcmeta` 的 26.3 数据包（`data/minecraft/enchantment`、`data/minecraft/tags/enchantment`）
- 算法核对：1.16.5 / 1.20.4 / 1.21.4 客户端反编译逐行比对；另与 [Earthcomputer/clientcommands](https://github.com/Earthcomputer/clientcommands) 的 `EnchantmentCracker` 互相验证
- 观测信息量、书架计划、扫描性能均为实测数据

## 说明

三档数字的算法从 1.16 起就没变过，所以破解对 1.16 – 26.3 通用；但「这一档出什么附魔」的池子随版本变化，本工具的附魔表按 1.21.4 / 26.3 制作，1.20.6 及更早只看种子更靠谱。

仅供单人存档、联机服里查自己的附魔台用。别拿去和服务端反作弊较劲。
